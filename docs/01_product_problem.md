## 1. Problem (ปัญหา)

### 1.1 ปัญหาที่พบจริง

**ฝั่งผู้บริโภค**

| ปัญหา | หลักฐาน / สิ่งที่สังเกตได้ |
|---|---|
| หาสินค้า OTOP ของจังหวัดตัวเองไม่เจอ | สินค้า OTOP กระจายอยู่ใน Facebook Group, LINE OA, ตลาดสด และเว็บของอบจ. แต่ละแห่ง — ค้นหาแยกทีละเว็บ |
| ไม่รู้ "ของถูก" กับ "ของแท้" | ข้อมูลผู้ผลิต วัตถุดิบ และที่มาของสินค้าแทบไม่มีบนแพลตฟอร์มทั่วไป ดูจากรูปอย่างเดียว |
| เชื่อร้านยาก | ร้าน OTOP มักไม่มีรีวิวจริง ไม่มีประวัติการจัดส่ง ลูกค้าจึงตัดสินใจจากความน่าเชื่อถือของแพลตฟอร์มแทน |
| สินค้าหลายแบบ (สี/ขนาด) สั่งยาก | ต้องทักไปถามในแชททีละรายการ แล้วรอ — เสียเวลาและบริการตกหล่น |

**ฝั่งผู้ประกอบการ OTOP**

| ปัญหา | ผลกระทบ |
|---|---|
| ไม่มีช่องทางขายออนไลน์ที่ถูก | อาศัยเพจส่วนตัว ตอบแชทคนละร้อยคน/วัน ไม่มีระบบกันลืม |
| ขายได้แค่ในจังหวัดตัวเอง | สินค้าถูกคนอื่น แต่เจ้าของไม่รู้ว่ามีคนอยู่อีก 76 จังหวัด |
| ไม่มีข้อมูลว่าอะไรขายดี | ตัดสินใจเพิ่มสต็อกจากความรู้สึก ไม่ใช่จากยอดขาย |
| สินค้าทำตามออเดอร์ ส่งช้า | ไม่มีสถานะคำสั่งซื้อ ลูกค้าทักมาถามซ้ำ → ร้านเสียชื่อ |

### 1.2 ทำไมแพลตฟอร์มที่มีอยู่แก้ไม่ได้

Shopee/Lazada สร้างบน **ปริมาณและความเร็ว** — สินค้า OTOP ซึ่งมีจำนวนน้อย ผลิตช้า และต้องอธิบายที่มาของสินค้า ไม่ใช่สินค้าที่ต้องขายให้เร็วที่สุด ดังนั้นการ "ทำ Shopee ใหม่" จึงไม่ใช่คำตอบ เพราะ:

1. โครงสร้างของแพลตฟอร์มใหญ่เอียงไปที่โฆษณาและ flash sale ซึ่งไม่ใช่จุดขายของ OTOP
2. สินค้า OTOP ต้องการ **เรื่องราวและความน่าเชื่อถือ** มากกว่า **ส่วนลด** — ซึ่งตรงข้ามกับสิ่งที่ทำให้แพลตฟอร์มใหญ่ประสบความสำเร็จ
3. ค่าธรรมเนียมของแพลตฟอร์มใหญ่คิดเป็น % ของมูลค่า ซึ่งกดรายได้ร้านเล็กจนไม่คุ้มเปิดร้าน

### 1.3 ปัญหาที่เราเลือกจะแก้

> **ทำให้คนไทยค้นพบ รู้จัก และสนับสนุนผู้ประกอบการ OTOP จากทั่วประเทศ ผ่านแพลตฟอร์มเดียวที่บอก "ของนี้ทำมาจากไหน ทำอย่างไร" ได้**

## 2. Target Users (ผู้ใช้เป้าหมาย)

### 2.1 Persona หลัก

**A. "เจ้าหน้าที่วางแผนปลายทาง" (ณ กรุงเทพฯ / เชียงใหม่) — ลูกค้าหลัก**
- อายุ 24–38 ปี รายได้ปานกลางถึงบน
- ต้องการของขวัญ/ของฝากที่ "มีเรื่องราว" ให้คนอื่น ไม่ใช่ของทั่วไป
- ยอมจ่าย 500–2,000 บาท/ชิ้น เพราะให้คุณค่าที่ซื้อไปเล่าได้
- **Pain:** หาเวลาไม่ได้ อยากได้ของดีโดยไม่ต้องเช็ค 20 เว็บ
- **ตัดสินใจซื้อเมื่อ:** เห็นจังหวัด + ชุมชนผู้ผลิต + รูปจริงหลายมุม

**B. "ลูกค้าของขวัญท้องถิ่น" (ต่างจังหวัด)**
- อยู่ต่างจังหวัด แต่อยากส่งของปลายทาง
- **Pain:** "ของฝากที่ซื้อจากร้านที่ไม่รู้จัก ไม่กล้าสั่ง"

**C. "ป้าสมชาติ/เจ้าของ OTOP" — ผู้ขายหลัก**
- ผลิตเอง หรือรวบรวมชุมชน ผลิตปีละ 2–4 รอบ
- อายุ 30–60 ปี ใช้ Facebook/LINE เป็นหลัก **อาจไม่ถนัดเทคโนโลยี**
- **Pain:** ไม่มีช่องทางขาย, ไม่เห็นยอดขาย, ไม่มีเวลาตอบแชท
- **ต้องการจากแอป:** กดเพิ่มสินค้าได้เร็ว, เห็นวันนี้ขายได้กี่ชิ้นทันที, เปลี่ยนสถานะคำสั่งซื้อได้ใน 2 กด

### 2.2 ใครใช้อะไร

```
Customer    → Home, Explore, Orders, Cart, Profile        (5 แท็บ)
Seller      → Dashboard, Products, Orders, Store, Profile  (5 แท็บ)
Admin       → จัดการข้อมูลพื้นฐานเท่านั้น (ไม่ทำ dashboard ซับซ้อน)
```

> **หมายเหตุเรื่อง role:** บัญชีเดียวถือหลาย role ได้ เพราะร้าน OTOP จริง ๆ คือคนที่ทั้งขายของตัวเองและโปรโมตของตัวเอง การบังคับให้เลือก role ตอนสมัครจะทำให้ UX แย่ลงโดยไม่ได้ประโยชน์

## 3. Value Proposition (ข้อเสนอคุณค่า)

### 3.1 สำหรับลูกค้า

> **"เจอสินค้า OTOP ทั่วประเทศ พร้อมเรื่องราวและคนที่ทำ — แล้วสั่งซื้อได้เลย ไม่ต้องทักไปถามทีละอย่าง"**

- ค้นหาจาก **จังหวัด/ภูมิภาค** ไม่ใช่แค่คำค้น — เพราะคนไทยซื้อของฝากเป็น "จากที่ไหน" มากกว่า "อะไร"
- ทุกสินค้ามี **Product Story** : ชุมชนผู้ผลิต, วัตถุดิบ, วิธีผลิต, เอกลักษณ์ — ตัดสินใจซื้อด้วยความรู้ ไม่ใช่ด้วยรูป
- **เลือกสี/ขนาดได้ในหน้าสินค้า** พร้อมเห็นสต็อก — ไม่ต้องทักไปถามก่อน
- เห็น **ค่าธรรมเนียมและคอมมิชชันอย่างโปร่งใส** ในใบเสร็จ

### 3.2 สำหรับผู้ขาย OTOP

> **"เปิดร้านขายทั่วประเทศได้ในวันเดียว โดยไม่ต้องมีทีมงานด้านเทคโนโลยี"**

- เพิ่มสินค้า + รูปหลายรูป + ตัวเลือกย่อย (สี/ขนาด) ใน 3 ขั้นตอน
- เห็น **ยอดขายวันนี้ / สต็อกที่ใกล้หมด / คำสั่งซื้อใหม่** เป็นอันดับแรกใน Dashboard
- อัปเดตสถานะคำสั่งซื้อเอง → ลดข้อความ "ของยังไม่ไปหรือเปล่า"
- ตั้งค่าค่าธรรมเนียมของร้านเองได้ (ค่าธรรมเนียมไม่บังคับตายตัว)

### 3.3 ราคา/ค่าธรรมเนียม (พูดตามจริง)

เรา **ไม่อ้างว่า** แพลตฟอร์มไม่มีค่าธรรมเนียมหรือถูกกว่าแพลตฟอร์มอื่น เพราะยังไม่มีข้อมูลรองรับ สิ่งที่เราอ้างได้คือ:

> "โครงสร้างค่าธรรมเนียมโปร่งใส และกำหนดให้เหมาะกับผู้ประกอบการไทยได้" — ร้านตั้งค่าเอง, แสดงยอดชัดเจนในใบเสร็จ

### 3.4 สิ่งที่ยังไม่ใช่ (ขอบเขตที่ปฏิเสธ)

- ไม่มี live streaming
- ไม่มี wallet / ถอนเงินจริง
- ไม่มีระบบ logistics เต็มรูปแบบ (ใช้การจัดส่งของร้าน + ติดตามสถานะ)
- **ไม่เชื่อม Payment Gateway จริงในเวอร์ชันนี้** — เป็น MVP Payment Flow ที่บันทึกสถานะจริงลง Firestore และออกแบบ Service ให้สลับเป็น Gateway จริงได้ภายหลัง

## 4. Differentiation (จุดต่าง)

| มิติ | แพลตฟอร์มทั่วไป | Thai OTOP Marketplace |
|---|---|---|
| จุดเริ่มค้นหา | คำค้น/หมวดสินค้า | **จังหวัด / ภูมิภาค** |
| ข้อมูลสินค้า | ชื่อ + ราคา + รูป | **+ เรื่องราว, ชุมชน, วัตถุดิบ, วิธีผลิต** |
| โมเดลรายได้ | โฆษณา + flash sale + ค่าคอมมิชชันทั่วไป | **ร้านตั้งค่าค่าธรรมเนียมเองได้ + แสดงโปร่งใสในใบเสร็จ** |
| จุดแข็ง | สินค้าเยอะ ราคาถูก | **คุณค่าและเรื่องราว ปริมาณน้อยแต่จำเป็น** |

## 5. สิ่งที่ตัดสินใจ **ไม่** ทำ (Scope Control)

ตัดออกเพื่อไม่ให้ scope บวมเกินคำถาม "ทำไม / ใครได้ประโยชน์ / ทัน deadline ไหม":

| ตัดออก | เหตุผล |
|---|---|
| ระบบโฆษณา / แบนเนอร์ | ต้องมีผู้ซื้อโฆษณาจริง ไม่ใช่แก้ปัญหาลูกค้า |
| แชทแบบ real-time แข่งกับ LINE | ทำให้ scope บวม และลูกค้า OTOP ใช้ LINE อยู่แล้ว (MVP ทำเป็น inbox ในแอป) |
| ระบบจัดส่ง/ชำระเงินจริง | ต้องมี contract กับผู้ให้บริการ เกินเวลาและเกินงบ |
| Multi-vendor cart แยกร้าน | ซับซ้อนมาก และ OTOP ส่วนใหญ่มีร้านเดียว — ทำแบบร้านเดียวก่อน |
| Social network | ไม่ใช่ปัญหาที่เราตั้งใจแก้ |
| ระบบ Affiliate / พาร์ทเนอร์ | ตัดออกจากขอบเขตเมื่อ **6 ต.ค. 2569** — รายละเอียดการตัดสินใจบันทึกไว้ที่ [`06_week_plan.md`](06_week_plan.md) |
