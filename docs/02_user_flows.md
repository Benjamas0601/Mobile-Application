> โฟลว์เหล่านี้คือ "เส้นทางหลัก" ที่ต้อง demo ได้ ไม่ใช่ทุกกรณีขอบเขนของฟีเจอร์

## 1. Customer — ค้นพบ → ซื้อ (โฟลว์หลักที่สำคัญที่สุด)

```
Login
  │
  ▼
Home ── 3D Hero + Search
  │
  ├─► พิมพ์คำค้น "ผ้าทอ" ─────────────► ผลลัพธ์ + Filter ─► Product Detail
  │
  └─► Explore Thailand ─► เลือกภูมิภาค ─► เลือกจังหวัด ─► ร้านในจังหวัด
                                                    │
                                                    ▼
                                             Product Detail
                                                    │
                              อ่าน Product Story (ชุมชน/วัตถุดิบ/วิธีผลิต)
                                                    │
                              เลือก Variant (สี/ขนาด) ── สต็อกไม่พอ ─► แจ้ง "สินค้าหมด"
                                                    │ สต็อกพอ
                                    ┌───────────────┴──────────────┐
                                    ▼                              ▼
                              Add to Cart                    แชทกับร้าน (ทางเลี่ยง)
                                    │                        (ส่งข้อความ/รูป)
                                    ▼
                                 Cart
                                    │
                        ใส่คูปอง ── ผิด/หมดอายุ ──► แจ้งเหตุผล ไม่ล้างตะกร้า
                                    │ ถูกต้อง
                                    ▼
                              Checkout (ยืนยันที่อยู่ + ยอด)
                                    │
                                    ▼
                          Payment (MVP Flow: เลือกวิธี + ยืนยัน)
                                    │
                                    ▼
                          Payment Confirmation ──► Order History ──► Order Detail
```

### จุดตัดสินใจสำคัญ (design decisions)

| จุดตัดสินใจ | ทำแบบนี้เพราะ |
|---|---|
| เลือก Variant **ก่อน** Add to Cart | ถ้าให้กด Add to Cart ก่อนแล้วค่อยเลือก ลูกค้าจะเพิ่มสินค้าผิดแบบแล้วต้องลบ — เพิ่ม friction และซับซ้อนเรื่องคืนเงิน |
| สต็อกไม่พอ → ปิดปุ่ม Add to Cart | ดีกว่าปล่อยให้กดแล้ว fail ตอน checkout |
| คูปองผิด → ไม่ล้างตะกร้า | ลูกค้าหลายคนพิมพ์โค้ดผิดพิมพ์ การล้างตะกร้าเป็นการทำร้าย UX |
| แชทเข้าถึงได้จากหน้าสินค้า | เป็นทางออกหลักของลูกค้า OTOP เมื่อไม่มีตัวเลือกย่อยที่ต้องการ |
| เข้า Cart ได้จากทั้งหน้า detail และรายการ | ลดจำนวนกดจากหน้า detail |

## 2. Seller — ลงสินค้า → ขาย

```
Login (บัญชีที่มี role = seller)
  │
  ▼
Seller Dashboard
  ├─ ยอดขายวันนี้ / สต็อกใกล้หมด / คำสั่งซื้อใหม่   ← เรียงตามลำดับความสำคัญ
  │
  ├─► แก้ไขร้าน (ชื่อ จังหวัด ชุมชน ผู้ผลิต เบอร์ ที่อยู่)
  │
  ├─► Products ──► เพิ่มสินค้า
  │                 1. ชื่อ + ราคา + หมวด + จังหวัด
  │                 2. อัปโหลดรูป (หลายรูป, รูปแรก = ปก)
  │                 3. ตัวเลือกย่อย (สี/ขนาด) + สต็อกแยกแต่ละแบบ
  │                 4. Product Story (ชุมชน/วัตถุดิบ/วิธีผลิต/เอกลักษณ์)
  │                 ── บันทึก ──► สินค้าขึ้น "ขายอยู่"
  │
  │      ยังไม่ครบ ─► แสดงเป็น "ฉบับร่าง" (ลูกค้าเห็นได้แต่ซื้อไม่ได้)
  │
  ├─► แก้ไข/ลบสินค้า ──► แก้ราคา/สต็อก/ตัวเลือกย่อย/รูป
  │
  └─► Orders ──► เปลี่ยนสถานะ: รอชำระเงิน → ชำระแล้ว → รอจัดส่ง → จัดส่งแล้ว → สำเร็จ
                (เปลี่ยนได้เฉพาะสถานะถัดไปตาม OrderStatus.allowedNext)
```

### กฎที่บังคับในโค้ด

- ผู้ขายแก้ไข/ลบได้ **เฉพาะสินค้าของร้านตัวเอง** (เช็คทั้งใน UI และ Security Rules)
- เปลี่ยนสถานะคำสั่งซื้อย้อนกลับไม่ได้ และข้ามสถานะไม่ได้ → ลดความสับสนของลูกค้า
- ลดสต็อกลงจนเป็น 0 → สินค้ายังคงอยู่ แต่สถานะเปลี่ยนเป็น `out_of_stock` และปุ่มซื้อถูกปิด (ไม่ลบสินค้าทิ้ง เพราะลูกค้าคนก่อนอาจอ้างอิงออเดอร์เก่า)

## 3. Affiliate — โปรโมต → ได้คอมมิชชัน

```
Login (บัญชีที่มี role = affiliate)
  │
  ▼
Affiliate Dashboard
  ├─ Clicks / Orders / Conversion / Commission
  │
  ├─► Products (สินค้าที่เลือกโปรโมตได้)
  │      └─► Generate Affiliate Link (เลือกสินค้า → ได้ลิงก์ที่มีชื่อตัวเอง)
  │
  ├─► Links ──► รายการลิงก์ของตัวเอง + จำนวนคลิกสะสม
  │
  └─► Commission
         ตัวอย่าง: สินค้า 500 บาท × คอมมิชชัน 5% = 25 บาท
         สถานะ: รอตรวจสอบ → อนุมัติแล้ว / ไม่อนุมัติ / ยกเลิก
```

> **ไม่มีการถอนเงินจริงใน MVP** — เป็น business logic ภายในระบบเพื่อสาธิตแนวคิด ตามที่กำหนดไว้

## 4. Admin — ดูแลระบบ

```
Login (role = admin)
  │
  ▼
จัดการ: Users / Stores / Products / Categories / Orders / Commission
  └─ หมวดหมู่สินค้าเป็นรายการที่ admin ต้องจัดการ (ร้านเลือกได้แค่หมวดที่ admin เปิด)
```

> ตั้งใจ **ไม่** สร้าง Admin Dashboard ซับซ้อน — ใช้เพียงรายการตารางพร้อมค้นหา/กรอง ตามที่บรีฟสั่ง

## 5. Error / Empty / Loading — ทุกโฟลว์ต้องมี

| สถานการณ์ | ข้อความที่ต้องแสดง | ปุ่ม |
|---|---|---|
| โหลดไม่สำเร็จ (เน็ต/Firestore) | "ไม่สามารถโหลดข้อมูลได้ กรุณาลองใหม่" | ลองอีกครั้ง |
| ไม่มีสินค้าในหมวด | "ยังไม่พบสินค้าในหมวดนี้" | ล้างตัวกรอง / ดูหมวดอื่น |
| ค้นหาไม่เจอ | "ไม่พบผลลัพธ์" | ลองค้นหาด้วยชื่อจังหวัด |
| ตะกร้าว่าง | "ตะกร้ายังว่างอยู่" | เริ่มเลือกสินค้า |
| ยังไม่มีคำสั่งซื้อ | "ยังไม่มีคำสั่งซื้อ" | ไปหน้า Home |
| ยังไม่มีการสนทนา | "ยังไม่มีการสนทนา" | เปิดรายการสินค้าเพื่อทักร้าน |
| คูปองผิด | "คูปองไม่ถูกต้องหรือหมดอายุ" (ตะกร้าไม่หาย) | — |
| สินค้าหมด | "สินค้าหมด" + ปุ่ม Add to Cart ถูกปิด | แจ้งเตือนให้ติดต่อร้าน |
| ยืนยัน order ไม่สำเร็จ | "บันทึกคำสั่งซื้อไม่สำเร็จ กรุณาลองใหม่" | กลับไป Checkout |

> หลักการ: **ไม่มีหน้าขาว ไม่มี error เงียบ** — ทุกกรณีต้องมีข้อความภาษาไทยที่ผู้ใช้อ่านรู้เรื่อง
